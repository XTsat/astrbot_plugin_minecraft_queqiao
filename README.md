## 功能介绍

通过 [鹊桥（QueQiao）](https://github.com/17TheWord/QueQiao) 模组连接 Minecraft 服务器与 AstrBot，实现群服消息互通与服务器管理。

- **群服互通**：游戏内聊天与群消息双向转发；回复 Bot 转发的游戏消息时，转发进游戏的内容自动附 `@原玩家名`，游戏内一目了然是谁在群里回复
- **图片互通**：群消息图片转发进游戏（需玩家安装 [ChatImage](https://github.com/kitUIN/ChatImage) 模组渲染）；游戏内图片 / 链接自动下载后发回群
- **事件播报**：玩家进出 / 死亡 / 成就事件转发到指定会话（死亡与成就原版端与 Velocity 不支持）
- **连通通知**：服务器连通 / 连接失败后向目标会话发送提示，文案可自定义
- **免打扰时段**：按服务器设置安静时段（如 `23:00` 至 `08:00`），时段内按类型静音游戏消息与连通通知，夜里不刷群
- **服务器管理**：状态查询、在线玩家列表、远程指令执行
- **Web 仪表盘**：服务器配置、状态与性能监控（TPS / 延迟）、互通终端日志、图床管理都能在面板里完成，无需改配置文件（详见「仪表盘能做什么」）
- **AI 聊天**：游戏内以 `#` 前缀发言即可与 AI 对话，回复私聊给玩家；会记住之前的对话（按服务器 / 目标群 / 每个玩家三选一），`#new` 开新对话、`#reset` 清空历史，与 AstrBot 自带指令同义
- **多服务器**：同时连接多台服务器，各自独立配置转发会话与开关
- **灵活连接**：正向连接（插件连鹊桥）或反向连接（鹊桥连插件，适合租赁服）

## 指令

| 命令 | 权限 | 说明 |
|------|------|------|
| `/mc help` | 全部 | 显示帮助信息与自定义指令列表 |
| `/mc status [编号\|地址]` | 全部 | 查看服务器状态（在线人数、延迟等） |
| `/mc list [编号\|地址]` | 全部 | 查看在线玩家列表 |
| `/mc player [编号] <玩家ID>` | 全部 | 查看玩家信息（依赖 RCON） |
| `/mc cmd [编号] <指令>` | 管理员 | 远程执行服务器指令，受黑白名单约束 |
| `/mc say [编号] <内容>` | 管理员 | 向游戏内广播消息 |
| `/mc bind <游戏ID>` | 全部 | 绑定你的游戏ID |
| `/mc unbind` | 全部 | 解除绑定 |
| `/mc servers` | 全部 | 查看已配置服务器与连接状态 |

多台服务器时在指令前加数字编号选择目标（如 `mc cmd 1 time set day` 定向第 1 台），仅一台服务器时可省略；`mc servers` 可查看各服务器编号。

`mc status` / `mc list` 支持**地址直连**：把参数换成 `host:port`（如 `mc status 127.0.0.1:25565`），插件直接以 Minecraft SLP 协议查询**任意**服务器（版本、在线人数、延迟、MOTD、玩家名），无需配置鹊桥；省略端口默认 `25565`。

### 自定义指令

`cmd.custom_cmd_list` 支持自定义快捷指令，格式：

```
触发词 <&参数&><<>>实际指令 {参数} {sender}
```

- `<<>>` 左侧为触发模板，右侧为实际执行的指令
- `{sender}` 替换为发送者**绑定的游戏 ID**
- `<&xxx&>` 为参数占位符，左右同名即按位置替换

示例：`tp <&X&> <&y&> <&z&><<>>tp {sender} <&X&> <&y&> <&z&>`——用户 A 绑定游戏 ID `Misaka` 后在群内发送 `tp 114 514 1919`，实际执行 `tp Misaka 114 514 1919`。

## 配置

### 完整配置编辑（仪表盘右上角「📝 配置」）

独立配置页已并入仪表盘：点右上角「📝 配置」在页面内切换出完整配置视图，按插件配置模板可视化编辑全部字段（含 MC 服务器、图片转存、转发与会话等），也可切到 JSON 模式直编辑；「💾 保存并重载」先备份再原子落盘并热重载，保存后自动刷新监控面板。返回监控点「📊 返回监控」。

### 仪表盘能做什么

仪表盘（插件 Pages 页面）里可以完成绝大部分日常操作，不必改配置文件：

**服务器条目**：点「＋ 新建服务器」填名称（与鹊桥 `config.yml` 一致）、显示名、连接方式与地址、Token、目标会话即可，其余字段按模板自动补齐。未启用的服务器以灰色卡片保留，点一下即可启用；运行中的也可一键停用。服务器名为空或与其它条目重名时，该条目会被跳过并以「未生效」灰卡显示，便于定位。每次保存都会先自动备份原配置，再落盘并热重载（断开旧连接按新配置重建）。

**🖼️ 图床标签**（服务器标签栏最右侧，进入后统计卡与服务器卡片区隐藏）：顶部直接切换总开关与上传超时；每个图床条目一张卡片，可新建 / 编辑 / 删除（删除需二次确认），并用「⬆ 上移 / ⬇ 下移」调整尝试顺序——上传时按列表从上到下依次尝试。`builtin_http` 条目额外显示运行中 / 未运行徽标。「🧪 测试上传」用内置 PNG 探针图跑一遍完整链路并回读产物核对格式：🟢 通过（ChatImage 能显示）、🟡 可用但受限（图床转成了 webp，传得上去但游戏里看不到）、🔴 失败（按「图床名: 原因」列出）。保存只重建图片转存子系统，不重连 MC 服务器；一台服务器都没配时图床也能独立工作。

**⚙ 功能设置抽屉**（右侧，折叠状态后端记住、跨设备保持，全部服务器视图下自动隐藏）：集中放不属于监控的开关——触发前缀（三个方向一行多选框统一启停，留空 = 全部命中）、消息转发（各类事件开关、聊天格式、群→MC 前缀与目标会话）、连接通知（连通 / 失败独立开关与文案）、互通终端加载天数。保存后写入插件配置并即时生效，不重建连接；与下方各配置表是同一份配置。性能监控自身参数仍在监控面板右上角「⚙ 设置」弹窗里。

### 自动刷新间隔

顶部「自动刷新」开关右侧有一个秒数输入框，直接改、失焦或回车即生效（10～3600 秒），不必再开弹窗；勾选「自动刷新」后按该间隔拉取面板数据。该间隔是**与具体服务器无关**的全局偏好。刷新 / 重新打开页面时，仪表盘停留在上一次打开的服务器标签，不再回到「全部服务器」。

### 服务器连通通知

<details>
<summary>服务器连通通知（6 项）</summary>

| 服务器状态探测地址 | string | 空 | 服务器状态探测地址（如 `127.0.0.1:25565`，可省略端口，默认 `25565`）：断线期间插件用它判断服务器是否真的停了；留空则按断线时长判断（超过 30 秒才发启动通知） |

</details>

两类通知都只发往该服务器的**目标会话**，未配置目标会话时不发送。模板里只有 `{display_name}`（服务器显示名称）与 `{server_name}`（服务器名称）会被替换，其余花括号原样保留；留空则用默认文案。

**连通通知（服务器已启动）**

服务器连通时会发一条「服务器已启动」。但它**只在服务器真的重启过时才发**——网络抖动、服务端卡顿、插件重载后重新连上，都不该让你以为服务器重启了。判断依据分两种情况：

- **填了「服务器状态探测地址」**：断线期间插件直接探测该地址。服务器仍在响应，说明只是 WebSocket 断了（不发通知）；探测不到才认为是真停了，恢复后发启动通知。这是最准的方式，推荐填写。
- **没填探测地址**：只能按断线时长判断。断开超过 **30 秒**才恢复才算「重启过」并发通知；几秒就自愈的抖动保持安静。

**连接失败通知**

覆盖两种情形：初次就连不上（服务器没开），以及已连接后断线。为避免刷屏，同一次故障（从断开到重新连上为止）**只发第一条**，后续重连失败不再重复；重新连上后，下一次故障才会重新通知。

断线后还会先等过「断连静默期」（默认 60 秒）才发失败通知：期间连回则一条都不发；超过静默期仍未恢复才通知。设为 `0` 则断线立即通知。反向模式下，失败通知只在**已建立的连接**断开时发送（等不到鹊桥连入不算）。

> 两者可以只开一个，也可以都开。只想在服务器真挂掉时被告知，开「连接失败通知」即可；想同时知道它恢复，再把「连通通知」也打开。

### 图片转发到游戏内（ChatImage）

开启 `forward_image_to_mc` 后，群消息以及已开启机器人自身转发的管道回复/自身群消息中的图片，以携带 URL 的广播形式转发进游戏，由玩家客户端自行加载渲染：

```
[QQ]群友A: [[CICode,url=https://example.com/images/example.png,name=图片]]
```

- 需为安装了 [ChatImage](https://github.com/kitUIN/ChatImage) 模组（Fabric / Forge / NeoForge）的服务器开启，否则只显示 `[[CICode,...]]` 文本
- 图片 URL 必须对玩家客户端可达；若图片没有公开 URL（日志提示「图片均无可访问的公开 URL」），开启 `image_upload.enabled` 并配置 `image_upload.services`（见下方）
- 配置了 `auto_forward_prefix` 时，只有带前缀的消息里的图片才会被转发（裸图片消息不带文本，不会命中前缀）

### 游戏内图片转发到外部会话

开启 `forward_image_from_mc` 后，游戏内聊天中的 ChatImage `[[CICode,url=...]]` 代码或图片链接会自动下载并作为图片发送到群：

- `http(s)://` 链接直接下载；`file://` 本地文件仅在 AstrBot 与游戏端同机时才能读取
- 下载失败（链接失效、本地文件不可见等）时保留原始代码/链接文本
- 单张图片上限 5 MB、下载超时 15 秒

#### E33Chat 模组支持

E33Chat 是另一套聊天模组（[NereaFantasia/E33Chat](https://github.com/NereaFantasia/E33Chat)）。把「游戏图片模式」设为 `e33chat` 后，插件会额外识别 `[[E33Emote,url=...]]`、`[[ChatUpgrade,url=...,type=image]]`（`type` 非 image 时忽略）与 `e33chat://media/<32 位十六进制>` 三种图片标记：

- **游戏 → 群**：三种标记都识别并下载成图片发到群
- **群 → 游戏**：图片写入服务端媒体目录后，以 `[[CICode,url=e33chat://media/<ID>]]` 发进游戏
- **服务端媒体目录**：E33Chat 的服务端媒体**没有 HTTP 端点**，图片直接存在服务端磁盘上，所以 AstrBot 必须能读到该目录（同机填路径，跨机需共享挂载）。留空时只能收发第三方图床链接，服务端媒体的图片会跳过并在日志提示一次。不想配共享目录的话，可在 E33Chat 客户端设置里关闭服务端媒体托管，它会回退到第三方图床（默认 uguu.se），发出的是公网链接，插件无需额外配置
- 群图默认缩到最长边 320 像素（可调 64–2048），避免撑满聊天面板

> 装了 ChatImage 的老版本 E33Chat（≤2.3.9）本身不渲染图片，图片仍由 ChatImage 显示，此时用默认的 `chatimage` 模式即可。

#### 内置图片 HTTP 服务

部分协议端收到的图片只有 base64 / 本地文件，没有对外可访问的 URL。此时在 `image_upload.services` 添加**「内置图片HTTP服务」**条目（模板 `builtin_http`），插件会把图片转存到内置 HTTP 服务，广播成 `{base_url}/img/<token>` 供玩家加载。**前提是 AstrBot 有公网地址**，且玩家客户端能访问到该地址。该条目可在仪表盘「🖼️ 图床」面板里直接维护，无需改配置文件。

## 部署与常见问题

### 前提

- **Minecraft 服务端**需先装 [鹊桥模组](https://github.com/17TheWord/QueQiao)——本插件只负责 AstrBot 这一侧，服务端不装鹊桥无法连通
- **AstrBot** 装好本插件即可，依赖由 AstrBot 自动安装

装好后在面板点「＋ 新建服务器」，**目标会话**必填，`server_name` 要与鹊桥 `config.yml` 的 `server_name` 一致。AstrBot 与 MC 同机部署时，连接信息已与鹊桥默认端口对齐，通常无需改动。

### 网络与地址（Docker / 同机部署）

`host` 填 `127.0.0.1` 还是 `0.0.0.0`，取决于 AstrBot 与 MC 是否在同一网络栈——判断依据只有一条：**鹊桥的监听地址能否被 AstrBot 直接访问到**。

| 场景 | 鹊桥 `websocket_server.host` | 插件 `ws_url` |
|------|------------------------------|---------------|
| 同机直装（同一网络栈） | `127.0.0.1`（默认） | `ws://127.0.0.1:8080/minecraft/ws` |
| 不同机器 | 该机器的可达地址（内网 IP 或 `0.0.0.0`） | `ws://<MC 服务器 IP>:8080/minecraft/ws` |
| AstrBot 在 Docker、MC 在宿主机（或反之） | `0.0.0.0` | 指向宿主机的可达地址 |
| 各自独立容器 | `0.0.0.0` | 指向 MC 容器的映射端口或容器名 |

> `0.0.0.0` 是**监听地址**（表示监听本机所有网卡），只能填在服务端一侧（鹊桥的 `websocket_server.host`、插件的 `reverse_host`）。`ws_url` 填「从 AstrBot 所在机器能访问到 MC 服务器」的地址。改了一侧，另一侧要同步改。

排查要点：

- 日志出现 `已连接鹊桥 (ws://...)` 才算成功，仅 TCP 可连通不代表握手通过
- 持续重连且无明确报错，多为鹊桥 `host` 仍为 `127.0.0.1`（容器内只绑 loopback，收不到 docker-proxy 转发的流量）
- 启动日志的 `WebSocket Server 在 <地址>:<端口> 启动...` 可确认实际监听地址

### 配置鹊桥

在 Minecraft 服务端安装 [鹊桥](https://modrinth.com/plugin/queqiao)，并按其[文档](https://github.com/17TheWord/queqiao-docs)配置 `config.yml`：

```yaml
# 以下三项必须与本插件配置对上
server_name: "Server"        # 必须与插件的「服务器名称」一致
access_token: ""             # 对应插件的「认证 Token」，留空则免鉴权

websocket_server:            # 正向连接（插件连鹊桥）用这段
  enable: true
  host: "127.0.0.1"          # Docker 等跨网络栈部署见上方
  port: 8080

rcon:
  enable: true               # 官方默认 false；mc cmd / mc list 需要它
  password: "your_password"  # 与 server.properties 的 rcon.password 一致

subscribe_event:             # 按需开启；关闭则收不到对应事件
  player_chat: true
  player_join: true
  player_quit: true
  player_death: true
  player_command: true
  player_advancement: true
```

反向连接时改用 `websocket_client`（`enable: true` + 在 `url_list` 填插件地址），并关闭 `websocket_server`。其余字段（`debug`、`message_prefix`、`enable_translation`、`ignored_commands` 等）保持默认即可，完整说明见[鹊桥文档](https://queqiao-docs.pages.dev/config/)。

### 常见问题

**Q：连接不上，提示鉴权失败或 404？** 检查 `server_name` 是否与鹊桥完全一致（含大小写），以及 `access_token` 是否相同。

**Q：`mc cmd` 没有输出？** 该指令依赖 RCON：在鹊桥 `config.yml` 设置 `rcon.enable: true` 并填密码；无法开启鹊桥 RCON 时，可在插件配置里启用「直连 RCON 兜底」。

**Q：`mc list` 不开 RCON 也能看到玩家名吗？** 可以。未开 RCON 时自动回退到在线查询（SLP `players.sample`），代价是名单可能不全（原版端截断、反 bot 插件留空或塞假名）；要完整名单仍需开 RCON，回报里会标注取数方式。

**Q：成就消息只显示「🏆 达成成就」？** 开启插件配置里的「本地翻译」（`enable_local_translation`）即可：插件自带翻译数据（`translations/`），按成就的翻译键 → 英文名精确表 → 原文逐级降级取中文，**不依赖服务端开翻译**。未开启时才会回落到服务端给的原文，原版端可能只有成就 key。
